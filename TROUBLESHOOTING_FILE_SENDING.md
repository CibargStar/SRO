# 🔧 Решение проблем с отправкой файлов (PDF) в кампаниях

## Проблема
Ошибка при отправке PDF файлов из мульти-шаблонов:
```
Message verification failed
File not found: ...
```

## Возможные причины

### 1. ❌ Файлы не скопированы в проект
Файлы шаблонов хранятся в `backend/uploads/templates/` и **НЕ** находятся в Git репозитории.

**Решение:**
- Скопируйте папку `backend/uploads/templates/` с вашего компьютера на компьютер коллеги
- Или загрузите файлы заново через интерфейс (создайте шаблоны заново)

### 2. ❌ Пробелы в пути к проекту
Если проект находится в папке с пробелами (например, `sro test`), могут быть проблемы с путями.

**Решение:**
- Переименуйте папку проекта, убрав пробелы: `sro test` → `sro-test` или `SRO`
- Или переместите проект в папку без пробелов

### 3. ❌ Миграции не применены
Если таблицы `templates` и `template_items` не созданы, файлы не будут работать.

**Проверка:**
```powershell
cd backend
npx prisma migrate status
```

**Решение:**
```powershell
cd backend
npx prisma migrate deploy
# или для development:
npx prisma migrate dev
```

### 4. ❌ Неправильный `process.cwd()`
Если сервер запускается не из папки `backend`, пути к файлам будут неправильными.

**Проверка:**
- Убедитесь, что вы запускаете `npm run dev` из папки `backend/`
- Проверьте логи - там должно быть `processCwd` с правильным путем

**Пример правильного запуска:**
```powershell
cd C:\Users\Magomed\Desktop\sro test\SRO\backend
npm run dev
```

## 🔍 Диагностика

### Шаг 1: Проверьте логи
При отправке файла в логах должно быть:
```
Starting file send { attachmentPath: "...", processCwd: "..." }
Resolved file path { originalPath: "...", resolvedPath: "..." }
File exists { filePath: "..." }
```

Если видите `File not found` - проверьте:
1. Существует ли файл по указанному пути
2. Правильно ли указан `processCwd`

### Шаг 2: Проверьте структуру папок
```powershell
# Должна существовать папка:
backend\uploads\templates\

# Внутри должны быть папки пользователей:
backend\uploads\templates\{userId}\{templateId}\{filename}.pdf
```

### Шаг 3: Проверьте БД
```powershell
cd backend
npx prisma studio
```

Откройте таблицу `template_items` и проверьте:
- Есть ли записи с `type = FILE`
- Заполнено ли поле `filePath` (должен быть относительный путь, например: `userId/templateId/filename.pdf`)

## ✅ Быстрое решение

1. **Скопируйте файлы:**
   ```powershell
   # На вашем компьютере:
   # Скопируйте всю папку backend\uploads\templates\
   # На компьютер коллеги вставьте в то же место
   ```

2. **Проверьте миграции:**
   ```powershell
   cd backend
   npx prisma migrate deploy
   ```

3. **Перезапустите сервер:**
   ```powershell
   # Убедитесь что запускаете из папки backend/
   npm run dev
   ```

4. **Проверьте логи при отправке:**
   - Должны появиться детальные логи о путях к файлам
   - Если файл не найден - проверьте путь вручную

## 📝 Важные замечания

1. **Файлы не в Git** - это нормально, они не должны быть в репозитории
2. **Относительные пути** - в БД хранятся относительные пути (например, `userId/templateId/file.pdf`)
3. **Абсолютные пути** - система автоматически преобразует их в `{process.cwd()}/uploads/templates/{relativePath}`
4. **Пробелы в путях** - могут вызывать проблемы, лучше избегать

## 🆘 Если ничего не помогло

1. Проверьте логи с детальной информацией о путях
2. Убедитесь, что файл существует на диске по указанному пути
3. Проверьте права доступа к файлу
4. Попробуйте загрузить файл заново через интерфейс
